## Release procedure

1. Start from a clean, reviewed source tree at a checked-out Git commit and install locked dependencies: `npm ci`.
2. Run `npm run verify`, then `npm audit --omit=dev --audit-level=high`. These perform typechecking, builds, tests, smoke coverage, and the required production-dependency vulnerability gate.
3. Validate the MCPB schema with the official CLI: `npx --yes @anthropic-ai/mcpb@2.1.2 validate manifest.template.json`.
4. Create the artifact: `node scripts/package.mjs`. It refuses to overwrite an existing `.mcpb` file.
5. Record the reported commit SHA, bundle SHA-256, and runtime SHA-256. Retain the artifact and staging `release-metadata.json` as inputs to the durable release record; they are not an acceptance packet by themselves.
6. Install without promotion: `.\scripts\install-release.ps1 -BundlePath <bundle> -ExpectedBundleSha256 <recorded-sha256>`. This verifies paths, identities, hashes, and byte counts, then creates a new immutable `releases\<version>+<sha7>` directory.
7. Set `$candidate = '<absolute-release-path>'`, then run `& "$candidate\operations\inspect-install.ps1"`. Resolve registration drift and state ACL warnings. A standalone repair requires a new external `-BackupPath`; use `protect-state.ps1 -StateDir <state-dir> -BackupPath <new-external-backup> -Force` only in an approved maintenance window. Its manual restore form requires the retained lowercase SHA-256.
8. Run the provider-disabled installed-artifact gate: `node .\scripts\canary-release.mjs --release-path <absolute-release-path> --install-root <absolute-install-root> --expected-version 0.3.0-rc.9 --expected-runtime-sha256 <recorded-runtime-sha256> --evidence-dir <absolute-durable-root>\installed-canary`. The new evidence directory must be outside the install root. Retain `canary-evidence.json`; it must report every required tool, exact runtime identity, zero providers, rejected Manus/Gemini delegations, zero post-attempt sessions/approvals, an unpromoted status, and unchanged shim/config/marker hashes. Then run `node .\scripts\canary-windows-shim.mjs --release-path <absolute-release-path> --install-root <absolute-install-root> --expected-version 0.3.0-rc.9 --expected-runtime-sha256 <recorded-runtime-sha256> --evidence-dir <absolute-durable-root>\windows-shim-canary`. A source-only unit result is not a substitute. In a host-quiescent window, also run `scripts\rehearse-rollback.ps1` with exact candidate/prior bundle hashes and a new private external evidence directory; it uses only a disposable install, but the trusted switch primitive still refuses while any MCP host is active.
9. Run provider-backed Codex and Claude canaries only against the absolute installed runtime. Set `AGENT_BRIDGE_SERVER_PATH`, `AGENT_BRIDGE_INSTALL_ROOT`, `AGENT_BRIDGE_EXPECTED_VERSION`, `AGENT_BRIDGE_EXPECTED_RUNTIME_SHA256`, and `AGENT_BRIDGE_LIVE_REQUIRED=1`; write each sanitized structured result to `<absolute-durable-root>\agent-runs\<backend>.json`. Stdout-only results are not retained evidence. Required mode rejects source `dist` and paths outside that install's immutable releases. A hash-verified config with Manus enabled derives `windows-local-manus`, but RC9 refuses an accepted packet for it because the existing Manus harness uses a disposable config and is not bound to the shared-config profile input. Its results remain diagnostic only. If Manus is disabled, combine the exporter-derived shared-config state with the structured disposable-config adapter-rejection canary; do not describe the canary alone as testing the shared config.
10. Declare a maintenance window and fully quit every MCP host; never terminate one from automation. Re-run `& "$candidate\operations\inspect-install.ps1"`, then `& "$candidate\operations\check-cutover-readiness.ps1"`; both the target bridge-process count and every repeated Codex/Claude host-family sample must be zero. A watcher may notify only and must never invoke Apply, restore, switch, cutover, or ACL mutations. Treat any detected fallback config whose canonical path or SHA-256 differs from the installed shared config as a cutover blocker before ACL mutation. Audit the state ACL before cutover: omit `-ApplyStateAcl` when it is compliant; otherwise provide a nonexisting external `-StateAclBackupPath` outside state and install, obtain explicit operator authorization, then add `-ApplyStateAcl`. Successful hardening is retained by `forward-only-security-hardening` even if later registration or promotion fails; the failure receipt identifies the retained backup path and SHA-256. For the currently known noncompliant state, use the complete single operator-run transaction `& "$candidate\operations\cutover-release.ps1" -ReleaseId <version+sha7> -StagedConfigPath <private-staged-core-config> -ExpectedConfigSha256 <exact-sha256> -ApplyStateAcl -StateAclBackupPath <new-external-acl-backup>` rather than separate Apply and switch commands.
11. After the pointer-only gate passes for RC9, restart one host first and repeat `diagnose_install`, `get_creator_status`, `get_budget_status`, `list_agents`, and a disposable read-only delegation before starting the remaining hosts. Re-export the schema-v2 record and require the config SHA-256, profile ID, sanitized capability projection, and `profileInputSha256` to match the pre-promotion values. Add or change policy only as a separate explicit offline operator action followed by a new acceptance packet.
12. After restarted-client and human acceptance, populate a schema-v2 descriptor from `examples\evidence-export-descriptor.example.json` inside the operator-controlled evidence root and run `npm run evidence:release -- --descriptor <absolute-descriptor.json> --output-dir <evidence-root>\<packet-id> --require-accepted`. The basename must equal `packetId`; every copied input must be a hash-pinned public/internal file canonically inside that root. The exporter derives the required checks from the hash-verified config; the descriptor's `expectedProfile` is only a mismatch guard. RC9 accepts only `windows-local-core`, which requires Manus/remote egress disabled and must say “Manus disabled; not live-certified.” `windows-local-manus` remains blocked until live artifacts are profile-input-bound; service maintenance or residual risk cannot waive that stop condition. Accepted export claims the shared cutover lock, rechecks the marker/shim/runtime/config, and holds the lock through packet rename and parent sync; an ownership/release failure removes the uncommitted packet and leaves an uncertain lock for manual inspection. Then run `npm run evidence:verify -- --packet-dir <absolute-packet-directory>`. Retain the resulting JSON, Markdown, manifest, and copied artifact hashes. The verifier checks packet hashes and internal profile consistency but cannot prove provenance against a party that rewrites both report and manifest. Promotion is provisional until this gate returns an accepted disposition for the derived profile. Export a truthful blocked packet without `--require-accepted` when cutover cannot yet proceed.

The MCPB 0.3 manifest is self-configuring for one selected creator project. It does not contain a fake config or secret. Advanced multi-root/write/remote policy continues to use the shared JSON config and stable shim workflow.

Ignored RC5/RC6/RC7/RC8 bundles and their `.release-staging` directories are historical artifacts only. They are not RC9 inputs and must never be promoted as the current candidate.

## Rollback

1. Fully quit every MCP host and confirm `activeProcessCount: 0` with `<trusted-release>\operations\inspect-install.ps1`.
2. Prefer `<trusted-release>\operations\switch-release.ps1 -ReleaseId <prior-version+sha7>`. Use the newest verified operational bytes even when targeting an older runtime. For emergency backup restore, restore `agent-bridge.mjs`, `config.json`, and `current-release.json` together according to `rollback-state.json`; remove the marker when the recorded prior state was absent.
3. Before restarting a host, run `scripts\canary-live-pointer.mjs` against the restored stable shim with the reviewed source Git, metadata, manifest, runtime, and exact rollback switch hashes, a new external evidence directory, and `--profile rollback-minimum`; this profile accepts only historical `0.2.1+4785d63`. It must validate immutable metadata/runtime, marker/shim/config binding, the core capability projection, MCP initialization and tool discovery proving `list_agents` is exposed without invoking it, zero delegation/session drift, and unchanged pointers. Then restart one host and confirm the restored runtime hash/version with `diagnose_install` when the prior release provides it; for v0.2.1, run `list_agents` and a disposable read-only delegation.
4. Restart the remaining hosts only after the canary passes. Do not delete either immutable release during the incident.
5. Preserve the failed artifact, its hashes, relevant host logs, and state directory for diagnosis. Do not copy credentials or plaintext session transcripts into an issue.

## Operational notes

- **Codex:** local CLI; supports resume and all bridge sandbox modes.
- **Claude:** local Claude Code CLI; its auth is separate from Claude Desktop/Cowork; supports resume and sandbox modes.
- **Manus:** remote API; supports task continuation but has no local filesystem/sandbox authority. Set up its key with `scripts/setup-manus.ps1`. Before enabling it, review the account's default skills and set `acknowledgeAccountDefaultCapabilities: true` plus a stable non-secret `accountCapabilityProfile`; the Manus API does not provide a bridge-enforceable switch to disable those defaults. A local-only preflight rejects a missing/empty configured credential, missing acknowledgement/profile, unsupported model, or finalized prompt above a conservative 4,500 UTF-8 byte ceiling before approvals or provider contact. Remote turn and confirmation approval envelopes bind the provider endpoint, connector/default-skill policy version, and account-profile label. New tasks request empty connectors/forced skills/references, and continuations request connector clearing, but those requests do not override account defaults. Ordinary continuation sends only to a `stopped` task. Use `reconcile_manus_task` for persisted `timed_out`, `aborted`, `error`, or `unknown` results: it requires remote-egress consent, classification, and current revision; performs GET-only polling; sends no message; and never stops the provider when its local window expires. Waiting remains on the specialized fixed-decision path. Confirmation revalidates the live provider action before consuming authority; after successful revalidation, the attempted-confirmation record is persisted immediately before POST. Waiting actions expose only browser skip, email save-as-draft, standard video, and high-credit rejection through inspect → preview → two exact approvals → confirm. Provider descriptions/schemas, native task IDs, and every wider action remain private or denied. A Manus `brief` proves no local-filesystem access only; it is not a provider-side no-side-effect or read-only guarantee. Record only bridge session/lifecycle plus sanitized SHA-256 correlations in public evidence.
- **Gemini:** local CLI; no native resume and cannot enforce bridge read-only mode.
- **Experimental daemon/proxy:** source/test API only. Do not deploy on Windows until user-only named-pipe ACL provisioning and verification exist; it is not an MCP transport yet.

Sessions are plaintext under `stateDir`, and locks prevent overlapping turns for a session. If a task needs confidential input, do not use the transcript as a secure store.
