The stable Codex and Claude registrations currently point to the immutable `0.3.0-rc.7+e082c8a` release. RC8 remains an unpromoted source candidate until every gate below is rerun against its own clean commit and immutable artifact. Do not switch registrations, restart hosts, or terminate bridge processes while user tasks are active.

## Verified scope

RC7 added the bounded `get_creator_status` overview, schema-2 partial recommendation recovery, evidence redaction, and a disposable candidate → prior → candidate rollback rehearsal. RC8 narrowly adds exact operation-free compatibility for the historical v0.2.1 manifest identity and initializes plus hash-verifies a provider-disabled shared fixture config before the rehearsal switches releases; the positive regression exercises candidate → v0.2.1 → candidate through the stable shim. Dynamic/custom `.cmd` and all `.bat` launchers remain rejected. The daemon remains library/test-only and is neither an MCP transport nor a packaged/registered service.

The approved Manus product review ran exactly once with a 50-cent maximum reservation. One recommendation used `ProposedChange` instead of `proposedChange`, so strict collection correctly returned `invalid-output`; local-only recovery produced eight advisory items without another provider call. Record its disposition as `invalid-output-recovered-advisory`, not a successful provider collection. Accepted/modified items drove creator status, partial sibling recovery, rollback rehearsal, and clearer reservation status. Blanket multi-action approvals were rejected because each consequential action must retain an exact hash-bound one-use approval.

On 2026-08-24, the installed RC7 Manus canary consumed its nonce-bound ticket but stopped before task creation because the configured credential was rejected as unauthenticated. A subsequent account attempt to create a replacement key returned `permission_denied` while the Manus service reported maintenance. Manus collaboration and live acceptance remain blocked until a new key is created, stored in the ACL-protected credential file, and passes a fresh installed-runtime canary.

Do not claim live backend availability from unit tests. A live Codex/Claude check requires the relevant CLI login and an allowed test root; Manus health requires a valid API key and network access.

## Release procedure

1. Start from a clean, reviewed source tree at a checked-out Git commit and install locked dependencies: `npm ci`.
2. Run `npm run verify`, then `npm audit --omit=dev --audit-level=high`. These perform typechecking, builds, tests, smoke coverage, and the required production-dependency vulnerability gate.
3. Validate the MCPB schema with the official CLI: `npx --yes @anthropic-ai/mcpb@2.1.2 validate manifest.template.json`.
4. Create the artifact: `node scripts/package.mjs`. It refuses to overwrite an existing `.mcpb` file.
5. Record the reported commit SHA, bundle SHA-256, and runtime SHA-256. Retain the artifact and staging `release-metadata.json` as inputs to the durable release record; they are not an acceptance packet by themselves.
6. Install without promotion: `.\scripts\install-release.ps1 -BundlePath <bundle> -ExpectedBundleSha256 <recorded-sha256>`. This verifies paths, identities, hashes, and byte counts, then creates a new immutable `releases\<version>+<sha7>` directory.
7. Set `$candidate = '<absolute-release-path>'`, then run `& "$candidate\operations\inspect-install.ps1"`. Resolve registration drift and state ACL warnings. If state inheritance is unsafe, inspect the target and run `.\scripts\protect-state.ps1 -StateDir <state-dir>` (or add `-Force` only in an approved unattended maintenance window).
8. Run the provider-disabled installed-artifact gate: `node .\scripts\canary-release.mjs --release-path <absolute-release-path> --install-root <absolute-install-root> --expected-version 0.3.0-rc.8 --expected-runtime-sha256 <recorded-runtime-sha256> --evidence-dir <absolute-durable-root>\installed-canary`. The new evidence directory must be outside the install root. Retain `canary-evidence.json`; it must report every strict-profile tool, the exact runtime identity, zero providers, an unpromoted status, and unchanged shim/config/marker hashes. Then run `node .\scripts\canary-windows-shim.mjs --release-path <absolute-release-path> --install-root <absolute-install-root> --expected-version 0.3.0-rc.8 --expected-runtime-sha256 <recorded-runtime-sha256> --evidence-dir <absolute-durable-root>\windows-shim-canary`. A source-only unit result is not a substitute. In a host-quiescent window, also run `scripts\rehearse-rollback.ps1` with exact candidate/prior bundle hashes and a new private external evidence directory; it uses only a disposable install, but the trusted switch primitive still refuses while any MCP host is active.
9. Run provider-backed Codex and Claude canaries only against the absolute installed runtime. Set `AGENT_BRIDGE_SERVER_PATH`, `AGENT_BRIDGE_INSTALL_ROOT`, `AGENT_BRIDGE_EXPECTED_VERSION`, `AGENT_BRIDGE_EXPECTED_RUNTIME_SHA256`, and `AGENT_BRIDGE_LIVE_REQUIRED=1`; write each sanitized structured result to `<absolute-durable-root>\agent-runs\<backend>.json`. Stdout-only results are not retained evidence. Required mode rejects source `dist` and paths outside that install's immutable releases. A skip is blocked evidence, never a pass. For Manus, run `npm run test:live:manus -- --evidence-dir <new-absolute-durable-directory>`, review the local-only preview and its exact ticket SHA-256, then separately run the emitted `--execute --confirm-ticket-sha256 <digest>` command. Preview contacts no provider; execution atomically renames the pending 15-minute ticket to a consumed record before launch and replay must fail. Retain the preview, consumed ticket, consumption record, and sanitized result. The ticket binds the installed runtime and credential identity, finalized prompt, model, timeout, data class, account-default capability acknowledgement/profile, connector-clearing policy, maximum reserved cost, and evidence paths.
10. Declare a maintenance window and fully quit every MCP host; never terminate one from automation. Re-run `& "$candidate\operations\inspect-install.ps1"`, then `& "$candidate\operations\check-cutover-readiness.ps1"`; both the target bridge-process count and every repeated Codex/Claude host-family sample must be zero. A watcher may notify only and must never invoke Apply, restore, switch, cutover, or ACL mutations. Treat any detected fallback config whose canonical path or SHA-256 differs from the installed shared config as a cutover blocker, including registrations parsed from single-quoted TOML. Use the single operator-run transaction `& "$candidate\operations\cutover-release.ps1" -ReleaseId <version+sha7>` rather than separate Apply and switch commands. It owns the install lock across repeated quiescence checks, registration normalization, the refusing maintenance barrier, and promotion; it restores client registrations if promotion fails and restores exact shim/config/marker state on any switch failure. Retain both backup paths. Omit the v0.3-only `policy.cumulativeRemoteCost` key from any disposable v0.2.1 rollback fixture because that strict historical runtime rejects the unknown key.
11. After the stable shim points to RC8, restart one host first and repeat `diagnose_install`, `get_creator_status`, `get_budget_status`, `list_agents`, and a disposable read-only delegation before starting the remaining hosts. Add or change `policy.cumulativeRemoteCost` only as a separate explicit offline operator action.
12. After restarted-client and human acceptance, populate a strict descriptor from `examples\evidence-export-descriptor.example.json` inside the operator-controlled evidence root and run `npm run evidence:release -- --descriptor <absolute-descriptor.json> --output-dir <evidence-root>\<packet-id> --require-accepted`. The basename must equal `packetId`; every copied input must be a hash-pinned public/internal file canonically inside that root. The accepted profile requires passing `windows-npm-shim-installed-runtime` automated and `manus-waiting-action-canary` remote-service checks; if no safe naturally occurring event exists, record it blocked and do not manufacture paid or consequential work. Then run `npm run evidence:verify -- --packet-dir <absolute-packet-directory>`. Retain the resulting JSON, Markdown, manifest, and copied artifact hashes. The manifest detects accidental or partial modification but is not a digital signature. Promotion is provisional until this gate returns an accepted disposition. Export a truthful blocked packet without `--require-accepted` when cutover cannot yet proceed.

The MCPB 0.3 manifest is self-configuring for one selected creator project. It does not contain a fake config or secret. Advanced multi-root/write/remote policy continues to use the shared JSON config and stable shim workflow.

Ignored RC5/RC6/RC7 bundles and their `.release-staging` directories are historical artifacts only. They are not RC8 inputs and must never be promoted as the current candidate.

## Rollback

1. Fully quit every MCP host and confirm `activeProcessCount: 0` with `<trusted-release>\operations\inspect-install.ps1`.
2. Prefer `<trusted-release>\operations\switch-release.ps1 -ReleaseId <prior-version+sha7>`. Use the newest verified operational bytes even when targeting an older runtime. For emergency backup restore, restore `agent-bridge.mjs`, `config.json`, and `current-release.json` together according to `rollback-state.json`; remove the marker when the recorded prior state was absent.
3. Restart one host first and confirm the restored runtime hash/version with `diagnose_install` when the prior release provides it. For v0.2.1, verify immutable metadata/runtime hashes plus the MCP initialization version, then run `list_agents` and a disposable read-only delegation.
4. Restart the remaining hosts only after the canary passes. Do not delete either immutable release during the incident.
5. Preserve the failed artifact, its hashes, relevant host logs, and state directory for diagnosis. Do not copy credentials or plaintext session transcripts into an issue.

## Operational notes

- **Codex:** local CLI; supports resume and all bridge sandbox modes.
- **Claude:** local Claude Code CLI; its auth is separate from Claude Desktop/Cowork; supports resume and sandbox modes.
- **Manus:** remote API; supports task continuation but has no local filesystem/sandbox authority. Set up its key with `scripts/setup-manus.ps1`. Before enabling it, review the account's default skills and set `acknowledgeAccountDefaultCapabilities: true` plus a stable non-secret `accountCapabilityProfile`; the Manus API does not provide a bridge-enforceable switch to disable those defaults. A local-only preflight rejects a missing/empty configured credential, missing acknowledgement/profile, unsupported model, or finalized prompt above a conservative 4,500 UTF-8 byte ceiling before approvals or provider contact. Remote turn and confirmation approval envelopes bind the provider endpoint, connector/default-skill policy version, and account-profile label. New tasks request empty connectors/forced skills/references, and continuations request connector clearing, but those requests do not override account defaults. Ordinary continuation sends only to a `stopped` task. Use `reconcile_manus_task` for persisted `timed_out`, `aborted`, `error`, or `unknown` results: it requires remote-egress consent, classification, and current revision; performs GET-only polling; sends no message; and never stops the provider when its local window expires. Waiting remains on the specialized fixed-decision path. Confirmation revalidates the live provider action before consuming authority; after successful revalidation, the attempted-confirmation record is persisted immediately before POST. Waiting actions expose only browser skip, email save-as-draft, standard video, and high-credit rejection through inspect → preview → two exact approvals → confirm. Provider descriptions/schemas, native task IDs, and every wider action remain private or denied. A Manus `brief` proves no local-filesystem access only; it is not a provider-side no-side-effect or read-only guarantee. Record only bridge session/lifecycle plus sanitized SHA-256 correlations in public evidence.
- **Gemini:** local CLI; no native resume and cannot enforce bridge read-only mode.
- **Experimental daemon/proxy:** source/test API only. Do not deploy on Windows until user-only named-pipe ACL provisioning and verification exist; it is not an MCP transport yet.

Sessions are plaintext under `stateDir`, and locks prevent overlapping turns for a session. If a task needs confidential input, do not use the transcript as a secure store.
