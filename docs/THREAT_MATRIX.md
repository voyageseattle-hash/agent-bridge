# Creator threat matrix

Use this matrix when planning a workboard and again before live promotion. A control marked as implemented still needs evidence from the candidate release.

| Boundary | Threat | Required control | Acceptance evidence | Residual decision |
| --- | --- | --- | --- | --- |
| Allowed project roots | Junction, symlink, or path normalization escapes the configured root | Canonicalize the allowed root and working directory, then recheck immediately before launch | Automated escape tests plus a disposable junction/symlink rejection | Do not accept any unresolved escape path |
| Local agent authority | Caller requests a stronger sandbox than configured | Enforce global and per-agent ceilings; require explicit configuration for `full-access` | Rejection tests for every over-ceiling request | Full access remains a high-trust operating mode |
| Windows local CLI launch | A `.cmd`/`.bat` shim reparses prompt, model, root, or extension arguments as shell commands | Spawn direct executables without a shell; resolve only canonical static npm `.cmd` shims to one contained Node entry point; reject dynamic/custom `.cmd` and all `.bat` launchers | Real space-path npm-shim test with hostile metacharacter argv and an untouched injection sentinel | Other batch wrappers require their underlying executable or a separately reviewed launcher |
| Concurrent work | Two agent sessions edit the same files | Keep cooperative workboards read-only; use one local integrator to apply accepted changes | Workboard record plus clean/diff evidence around the integrator step | Session locks do not provide workspace ownership |
| Remote Manus call | Private context leaves the machine or account-default skills/connectors widen capability without informed consent | Config allowlist plus exact root/agent/data-class approval and per-call remote consent; require explicit acknowledgement/profile for account defaults; bind provider endpoint, request-capability policy version, and account-profile label; request empty connectors/forced skills/references and connector clearing on continuation | Approved and consumed `remote_egress` record; finalized-prompt SHA-256; full approval-envelope SHA-256; capability profile; sanitized correlation hashes | Provider retention and account-default capabilities remain external dependencies; the profile is operator-attested rather than provider-enumerated, and clearing request fields cannot override account defaults |
| Manus local preflight | Known-invalid credential, model, or prompt consumes approval/budget before provider rejection, or ordinary continuation bypasses unresolved/waiting state | Before preview/consumption, locally require a non-empty configured credential, explicit account-default acknowledgement/profile, a supported model, and a finalized prompt within the conservative 4,500 UTF-8 byte ceiling; allow ordinary continuation only from persisted `stopped`, and keep `waiting` on confirmation | Focused no-network preflight tests; zero approval/budget mutation on rejection; lifecycle tests prove no ordinary send from unresolved or waiting state | Persisted lifecycle can lag the provider and must be reconciled explicitly |
| Manus task reconciliation | Retrying an ambiguous timed-out/aborted/error/unknown turn duplicates the user message or a local timeout stops paid provider work | Require current session revision plus remote-egress consent/classification; use `reconcile_manus_task` for GET-only polling; send no message and never issue stop on local reconciliation timeout | Request-method tests; unchanged provider message count; revision-mismatch rejection; unknown result records `reconciliationTimedOut` without `stopRequested` | GET polling contacts the provider, provider state can change during/after polling, and account-default capabilities still apply |
| Remote/paid task | Concurrent sessions, retries, or an unknown model oversubscribe the creator's intended spend | Bounded timeout/retries; one-time `paid_or_unknown_cost` approval bound to the complete approval envelope; optional atomic state-wide reservation ceiling with a non-reclaimable token-owned lock and ledger-loss marker | Approval record, pre-launch budget snapshot, bridge session/lifecycle, sanitized request/response correlation hashes, final state, and reported cost/credits when available | Reserved approved maxima differ from billed cost; conservative local failures can burn budget; OS/power-loss durability depends on the filesystem; a local principal who can remove all budget state can reset the boundary; CLI-provider accounts remain outside this breaker |
| Manus waiting action | A provider-controlled event widens authority, leaks its dynamic schema/description, changes after preview, is confirmed twice, or races a session/account-capability change | Discard provider description/schema; allow four fixed decisions only; bind task/event/type/input plus provider endpoint/policy/account profile; require unchanged session revision and fresh one-time approvals; revalidate the live action before authority consumption; after revalidation persist the attempt immediately before POST | Preview execution envelope/scope/hash; proof that stale live action consumes no approval/budget; attempted marker ordered immediately before POST; accepted marker, terminal turn, and focused concurrency/adversarial tests | A response lost after provider acceptance is inherently ambiguous; consumed approval/budget remains conservative and requires operator reconciliation |
| Prompt/context handoff | Agent output contains instructions that override operator intent | Bound and escape handoff context; label it untrusted; start independent reviews fresh | Injection regression tests and prompts that preserve the trust boundary | A model can still reason incorrectly about untrusted text |
| Credentials | Key enters source, transcript, error detail, manifest, or evidence export | Store only in the protected credential file/environment; reject secret-like approval text; redact public diagnostics | Repository secret scan, ACL report, and a key-rotation record without the key value | Plaintext exists in the authorized process memory |
| Manus capability claim | Remote agent is treated as if it inspected local files, or `brief` is misrepresented as provider-side read-only/no-side-effect execution | Report no local-filesystem authority; reject `brief` scope for any backend with local-filesystem capability; isolate and sanitize the Manus brief; state explicitly that provider-side capabilities are not disabled | Recommendation scope says `brief`; `briefSha256` identifies the supplied text; claims cite only supplied artifacts | Remote artifact freshness/identity and provider-side behavior must be established separately; account-default skills remain external |
| Artifact/evidence reference | A path, URL, or label is mistaken for verified content | Treat references as inert metadata; record SHA-256, media type, data class, and accessibility | Hash verification performed by an authorized step and recorded as a check | A correct hash does not prove the artifact is safe or useful |
| Approval record | An agent self-asserts that a human approved an action | Display exact scope for explicit human decision; append immutable decision/consumption events | Actor/reason/timestamp/event history and exact-scope match | Workflow identity is not cryptographically attested |
| Sessions/workboards | Plaintext prompts, outputs, and client data leak from state storage | Protect state ACL, minimize payloads, define retention, never store credentials | `inspect-install.ps1` ACL result and retention review | OS administrators and the user account can read plaintext state |
| Cancellation | A timed-out or canceled child continues running | Propagate abort signals and kill the process tree on Windows; bound remote polling | Cancellation tests plus no surviving test child/task polling | Provider-side work may require explicit remote cancellation support |
| Client registration | One client pins a stale release or reads a different source/fallback config | Register every client to the stable shim and installed shared config; inspect registration and fallback-config drift, including single-quoted TOML | Dry-run/apply report, canonical config paths/hashes, zero fallback divergence, and per-host `diagnose_install` identity | Hosts cache MCP servers until fully restarted |
| Artifact packaging | Bundle is stale, partial, or differs from the tested build | Package from a clean commit, publish atomically, verify metadata, size, and SHA-256 | Verify run, source SHA, bundle/runtime hashes, official manifest validation | Supply-chain trust still includes locked dependencies and toolchain |
| Live promotion | The stable shim changes while hosts are active | Refuse switching with matching Agent Bridge processes; canary immutable release first | `activeProcessCount: 0`, backup path, promotion marker, post-restart checks | Process detection should be reviewed when host launch patterns change |
| Rollback | Recovery destroys the failed state or restores the wrong build | Keep immutable releases and timestamped backups; verify identity before switch | Prior release ID/hash, backup path, rollback canary | Stateful schema incompatibility may need separate migration planning |
| Quality claim | Unit tests are presented as real creator acceptance | Separate automated, local CLI, remote service, client-restart, and human-visible gates | Completed [LIVE_ACCEPTANCE.md](LIVE_ACCEPTANCE.md) with status per gate | Subjective usefulness still needs creator judgment |

## Stop conditions

Do not proceed to live promotion when any of these is true:

- A credential used by the candidate was exposed and has neither been revoked nor covered by the operator's explicit documented acceptance of that residual risk. Such acceptance never counts credential hygiene as passed.
- The source tree, release identity, runtime hash, or registration target is ambiguous.
- Any Agent Bridge process under the install root is active during a switch or registration apply.
- Required tests, schema validation, or the immutable-release canary failed.
- A remote or paid action lacks a fresh exact-scope approval.
- A configured direct-remote budget ledger is corrupt, exhausted, or cannot reserve a positive bounded maximum before launch.
- A recommendation claims local evidence from Manus without a supplied, identified artifact.
- Manus is enabled without explicit acknowledgement and a stable account-capability profile for the default skills that Agent Bridge cannot disable.
- An explicit or fallback client config resolves somewhere other than the installed shared config or has a different SHA-256.
- A Manus waiting event asks for anything outside browser skip, email draft, standard video, or high-credit rejection.
- Rollback identity or backup location has not been recorded.
