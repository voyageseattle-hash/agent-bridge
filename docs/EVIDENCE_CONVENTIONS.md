# Evidence export conventions

Keep JSON for machine checks and Markdown for creator review. Both exports must describe the same run and use stable identifiers.

## Required rules

- Set `schemaVersion` and `packetId`; never silently change field meaning.
- Use UTC ISO 8601 timestamps and lower-case SHA-256 hex.
- Record the exact command, exit code, and sanitized output reference for mechanical checks.
- Use absolute local paths only in private local evidence. In shared exports, replace personal prefixes with labels such as `<workspace>` and `<state-dir>`.
- In shared evidence, reference secrets only by an abstract credential name or `<credential-file>` placeholder. Keep actual protected file paths in private evidence or config. Never include credential values, environment dumps, authorization headers, or raw config contents.
- Store large output outside the summary and reference it by URI/path plus SHA-256 and byte count.
- Preserve agent runs separately. Aggregation must retain source agent IDs and invalid/failed statuses.
- Distinguish `automated`, `local-cli`, `remote-service`, `client-restart`, and `human-visible` checks.
- Use `pass`, `fail`, `blocked`, or `not-run`. Include `reason` for every status other than `pass`.
- An artifact reference is metadata, not proof. A check must state how the artifact hash, contents, or behavior was verified.
- Sanitize copied stderr, prompts, transcripts, URLs, usernames, and provider details before export. Record the sanitization method.
- Keep approval request, decision, and consumption events. Do not represent a pending or mismatched approval as authorization.
- For new releases, use descriptor/report schema v2. Schema v1 remains readable with its original unconditional acceptance profile; never reinterpret a historical v1 packet under v2 rules.
- Treat `acceptancePolicy.expectedProfile` only as an operator guard. The exporter derives the actual profile from the exact shared-config bytes after checking `candidate.configSha256`.
- Record disabled capabilities explicitly. `windows-local-core` means Manus and Gemini are disabled and not live-certified; it does not mean Codex or Claude are offline.
- A residual risk can document a deviation but cannot satisfy or waive a check selected by the derived profile.
- `evidence:verify` checks packet hashes and internal profile/digest consistency. Because the packet intentionally omits raw config and is not signed, it cannot independently reconstruct the original config or defeat a party that rewrites both report and manifest; source-backed derivation is an exporter-time claim.

The canonical release packet is generated by `npm run evidence:release`; the checked-in examples document the schema only. Put the descriptor and every copied input under one operator-controlled `evidenceRoot` outside the install root. Protect that root's ACL separately. Only hash-pinned `public` or sanitized `internal` text/JSON may be copied; `confidential` and `restricted` artifacts are rejected. The new output directory must also be inside that root and its basename must equal `packetId`. Use `--require-accepted` only after the candidate is promoted and every check selected by the derived capability profile passes. Accepted export claims the same durable install cutover lock as release switching and holds it through final live-binding verification, packet rename, and parent sync; an existing or stale lock fails closed and must not be reclaimed automatically. Descriptor facts remain operator attestations; the profile itself is exporter-derived from the hash-verified config and is bound to release ID, runtime SHA-256, and config SHA-256 through `profileInputSha256`. Changing any config byte requires a new packet. The exporter redacts configured roots, common credentials, URLs, and absolute paths, but it is not a semantic DLP classifier: the operator remains responsible for removing sensitive business content that does not resemble a credential or path. Generated reports include source/export SHA-256 values, byte counts, commands, exit codes, UTC timestamps, sources, and truthful statuses. Run `npm run evidence:verify -- --packet-dir <absolute-packet-directory>` after copying or opening an archive. A manifest detects missing, extra, or accidentally changed files; it is not a signature and cannot prove integrity against a malicious editor who rewrites both content and hashes. Manual edits require a new export.

## JSON packet

The canonical example is [evidence-report.example.json](../examples/evidence-report.example.json). Keep these top-level groups:

- `candidate`: source, bundle, runtime, config identity, and live/candidate distinction.
- `acceptance`: derived profile, sanitized capability projection, and profile-input digest. It never contains raw config, roots, credentials, remote allowlists, or account-profile labels.
- `checks`: typed checks with commands/evidence and truthful status.
- `approvals`: identifiers and exact scopes, without secrets.
- `agentRuns`: separate local/remote run results and output references.
- `recommendations`: accepted/rejected/deferred decisions linked to sources.
- `workboard`: lifecycle and per-item acceptance state.
- `residualRisks`: unresolved risk, owner, disposition, and review date.
- `rollback`: prior identity, backup reference, and canary result.

## Markdown packet

The canonical example is [evidence-report.example.md](../examples/evidence-report.example.md). It should answer, in order:

1. Which capability profile was derived, and which integrations are explicitly disabled or not certified?
2. What exact candidate was evaluated?
3. What passed automatically?
4. What passed in each selected live client/service?
5. What remains blocked or unverified?
6. Which human approvals were consumed?
7. Which recommendations were accepted, rejected, or deferred?
8. Can the operator roll back to a named verified release?

Do not paste the full JSON into Markdown. Link or name the JSON artifact and record its SHA-256.

## Redaction vocabulary

Use consistent placeholders so review can distinguish redaction from missing evidence:

| Placeholder | Meaning |
| --- | --- |
| `<workspace>` | Canonical allowed project root |
| `<state-dir>` | Protected Agent Bridge state directory |
| `<install-root>` | Stable Agent Bridge install root |
| `<credential-file>` | Path to a secret file; never its contents |
| `<redacted-secret>` | A secret value was removed |
| `<redacted-user>` | A local account name was removed |
| `<provider-detail-redacted>` | Provider response detail was bounded or removed |

If redaction prevents reproduction, keep the complete evidence only in the authorized local archive and record its hash in the shareable packet.
